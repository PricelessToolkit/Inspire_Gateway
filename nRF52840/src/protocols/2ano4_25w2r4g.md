# `2ANO4-25W2R4G` RF protocol

This is the confirmed gateway implementation for the third ceiling-light
remote. The name came from an FCC lead, but it remains a convenient research
label: the captured remote has not been proven to be the exact device in that
filing. The filing says 2450 MHz; this physical remote transmits near
2406.943 MHz.

## Confirmed RF behavior

| Property | Value |
|---|---|
| UART plugin ID | `2ANO4-25W2R4G` |
| Measured carrier center | approximately 2406.943 MHz |
| nRF channel | 7 / nominal 2407 MHz |
| Modulation | binary GFSK, approximately 1 Mbit/s |
| Measured deviation | approximately +/-126 kHz |
| Measured 95% occupied bandwidth | approximately 0.97 MHz |
| Hardware address | `4E22C32B40` |
| Hardware preamble | 16 bits |
| Hardware body | 188 bytes, fixed length |
| Whitening | disabled |
| Hardware CRC | disabled |
| Repeat interval | 3406.25 us |
| Native quick press | approximately 150 frames / 0.52 s |
| Frequency hopping | none observed |
| nRF TX power | +8 dBm |

The nRF52840 successfully receives the remote using a 16-bit preamble,
five-byte address, and 188-byte static body. Before the normal frame, the real
remote emits an approximately 87-bit wake/AGC leader. Directly transmitting the
188-byte packet without that leader did not control the light.

The working transmitter sends the leader as a short preliminary radio packet,
then immediately sends the correctly framed 188-byte packet with address
`4E22C32B40`. An earlier attempt to embed the real preamble inside one larger
dummy packet failed because a packet receiver cannot normally re-lock to a new
preamble while it is already consuming a packet.

## Actions and short UART payloads

| Action | Eight-byte fingerprint |
|---|---|
| ON | `38103B2650AB2B39` |
| OFF | `229D6A0896C4F0CB` |
| Brightness up | `00E028A6B3650AFC` |
| Brightness down | `260C7F154AB22929` |
| Warmer | `1238BD39812E228B` |
| Colder | `13F018B8A0853B96` |
| Default brightness/color | `0513E01CE9636422` |

The fingerprint begins at bit offset 857 of the received 188-byte body and is
not byte-aligned. It is sufficient for RX identification, but it is not a
standalone packet. The latter part of the frame contains repeated or encoded
companion data. Replacing only those 64 bits in an ON body creates an invalid
hybrid frame.

The plugin contains one directly captured, complete valid frame for every
known action. When it receives an eight-byte UART payload from the table, it
expands that fingerprint to the corresponding full 188-byte frame. It also
accepts a complete 188-byte body for research or exact replay.

Examples:

```text
TX protocol=2ANO4-25W2R4G address=4E22C32B40 repeat=150 payload=38103B2650AB2B39
TX protocol=2ANO4-25W2R4G address=4E22C32B40 repeat=150 payload=229D6A0896C4F0CB
TX protocol=2ANO4-25W2R4G address=4E22C32B40 repeat=150 payload=00E028A6B3650AFC
TX protocol=2ANO4-25W2R4G address=4E22C32B40 repeat=150 payload=260C7F154AB22929
TX protocol=2ANO4-25W2R4G address=4E22C32B40 repeat=150 payload=1238BD39812E228B
TX protocol=2ANO4-25W2R4G address=4E22C32B40 repeat=150 payload=13F018B8A0853B96
TX protocol=2ANO4-25W2R4G address=4E22C32B40 repeat=150 payload=0513E01CE9636422
```

Allow approximately `repeat * 3.40625 + 5` milliseconds before sending the
next command. For 150 repeats, wait at least 516 ms; 525 ms is convenient.

## Reception

Normal RX output contains the compact fingerprint:

```text
RX protocol=2ANO4-25W2R4G time_us=114622070 rssi=-55 address=4E22C32B40 len=8 s1=0 payload=229D6A0896C4F0CB
```

USB can additionally dump complete received radio bodies with `DUMP_RX` or
`DUMP_RX_ALL`; these diagnostics are described in the modem README. Hardware
UART continues to send the normal compact RX line expected by the ESP32.

Two presses per button were captured directly through the nRF receiver. ON,
OFF, and DEFAULT produced stable captured full frames. Incremental brightness
and temperature actions showed two alternating valid full-frame variants while
keeping the same eight-byte action fingerprint. The plugin stores one captured
valid variant for each action.

## Hardware validation

The following were physically confirmed on the ceiling light with 150 repeats:

- complete-frame ON replay: worked;
- complete-frame OFF replay: worked;
- complete-frame brightness-down replay: worked;
- short fingerprint expanded to brightness-up: worked;
- short fingerprint expanded to warmer: worked;
- short fingerprint expanded to colder: worked.

DEFAULT was transmitted successfully but its visible effect was inconclusive
because the light appeared to be at its default state already.

The implementation is [`2ano4_25w2r4g.h`](2ano4_25w2r4g.h). After any TX,
this plugin remains selected and the radio automatically returns to listening
on channel 7.

`address` is required and dynamically configures the five-byte RF header. The
stored compact-action frames were learned from the remote using `4E22C32B40`.
Another same-model light may also encode a pairing identity inside the 188-byte
body, so a new address alone must not be assumed sufficient without capturing
and testing that remote.
